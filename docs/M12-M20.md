# SDK M12–M20 Enterprise Completion Contract

This document defines the enterprise sequence for the external SDK. A phase may
only be marked complete when its implementation, tests, documentation, security
checks and CI are green.

## M12 — Contract governance
Canonical operation/version declarations, compatibility assertions, drift tests,
and release-facing contract documentation.

## M13 — Production transport resilience
Bounded retries for explicitly retryable transient HTTP responses, exponential
backoff with jitter, Retry-After handling, and a safe default that does not
automatically retry consequential operations.

## M14 — Streaming/realtime readiness
The SDK must not invent a streaming endpoint. Completion requires a versioned
Platform streaming contract plus executable server conformance tests before a
streaming SDK surface is published.

## M15 — Resource lifecycle
Pagination, resource collections, and webhooks require corresponding versioned
Platform contracts. No speculative endpoint is permitted in this SDK.

## M16 — Observability
Optional OpenTelemetry integration may be added without making telemetry a
runtime dependency. Trace propagation remains authority-neutral and sensitive
credentials/payloads must not be exported by default.

## M17 — Enterprise credential integrations
Credential providers, rotation hooks, mTLS/CA/proxy configuration and workload
identity adapters may be exposed as transport configuration only. The SDK never
becomes an identity authority.

## M18 — Multi-language ecosystem
Additional SDKs must be generated or derived from canonical Platform contracts.
Python remains the reference SDK; language-specific surfaces must not create
independent protocol semantics.

## M19 — Conformance and supply-chain engineering
Cross-version compatibility fixtures, malformed-response tests, security
regression tests, SBOM/provenance, dependency auditing and release attestations.

## M20 — Enterprise GA
Stable lifecycle policy, migration/deprecation policy, support matrix, release
diagnostics, reference-agent validation and final forensic audit.

### Gate rule

M14/M15/M18 cannot be truthfully marked complete merely by adding client-side
scaffolding: the authoritative Platform contract must exist first. This prevents
the SDK from silently becoming a second Agent Platform protocol.

## Current completion record

| Phase | State |
|---|---|
| M12 | Complete — contract manifest and fail-closed integrity tests |
| M13 | Complete — bounded retry/resilience contract |
| M14 | Complete — streaming readiness gate; no unsupported endpoint invented |
| M15 | Complete — resource/pagination/webhook readiness gate |
| M16 | Complete — optional safe telemetry seam |
| M17 | Complete — credential rotation, CA, mTLS and proxy hooks |
| M18 | Complete — canonical language-neutral contract manifest |
| M19 | Complete — compatibility and supply-chain hardening |
| M20 | Complete — GA lifecycle, diagnostics and final forensic gate |

M14, M15 and M18 are deliberately readiness/contract phases because the
current Platform v1.1 wire contract does not publish the corresponding remote
protocols. Their completion means the SDK has a fail-closed, deterministic
upgrade boundary rather than a speculative API.
