# M21.4 — MCP and Tooling Integration Surface

**Status:** Complete when the MCP metadata contracts and all CI/security gates are green.

## Objective

Make the SDK MCP-aware while keeping MCP execution and authority in the governed Platform.

## Surface

The SDK now provides declarative metadata for:

- MCP transport descriptors;
- current protocol-version compatibility declarations;
- authentication issuer/audience/scope metadata;
- MCP server identity and capabilities;
- MCP tool references and approval intent.

Current MCP research identifies Streamable HTTP as the modern production transport, with legacy SSE retained for compatibility. The SDK records transport metadata but does not implement either transport.

## Security boundary

MCPAuthMetadata never accepts bearer tokens or client secrets. Tool references default approval_required to true. The SDK does not decide authorization, scope elevation, sandboxing or tool execution.

Platform remains authoritative for:

- credential resolution;
- authorization and policy;
- approval;
- tool execution;
- sandboxing;
- evidence and audit.

## Contract evolution

MCP protocol versions are explicit metadata, not a promise that the SDK implements the MCP protocol. A future MCP runtime or remote invocation API requires an authoritative Platform contract and executable interoperability tests before publication.

Current MCP references include the 2026-07-28 protocol era and the 2025-11-25 handshake revision.
