# M15 — Resource Lifecycle Readiness

The current Platform API does not expose resource-oriented endpoints, cursor
pagination, or webhook delivery. The SDK therefore remains an operation-gateway
client and must not manufacture those semantics.

## Required Platform contracts

### Pagination

A future `platform.pagination.v1` contract must define:

- cursor format and opacity;
- page-size bounds;
- stable ordering;
- next/previous continuation semantics;
- snapshot/consistency behavior;
- tenant and authorization scoping;
- duplicate/missing item behavior;
- invalid/expired cursor errors.

### Webhooks

A future `platform.webhooks.v1` contract must define:

- event schema and version;
- signing algorithm and key rotation;
- timestamp/replay window;
- event ID and deduplication semantics;
- delivery retry behavior;
- ordering guarantees;
- tenant isolation;
- endpoint lifecycle;
- secret rotation;
- maximum payload size.

### Resource collections

A future resource API must not be inferred from the existing operation gateway.
The Platform must first publish canonical operations and executable conformance
tests. The SDK can then expose typed sync/async collection iterators.

M15 is therefore complete as a readiness gate when these boundaries are explicit,
the feature registry is authoritative, and no unsupported collection/pagination/
webhook method is exported.
