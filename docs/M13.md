# M13 — Production Transport Resilience

M13 is complete only when retry behavior is bounded, deterministic enough for
testing, safe for consequential operations, and covered across supported
Python versions.

## Contract

- Retryable HTTP statuses: 429, 502, 503, 504.
- Maximum attempts are explicit and bounded by `RetryPolicy.max_attempts`.
- Backoff is exponentially bounded by `max_delay`.
- Jitter is bounded by the configured fraction.
- A valid `Retry-After` value is honored and capped by the retry budget.
- HTTP-date and delta-seconds forms are accepted.
- Consequential operations are not retried by default.
- Consequential retry requires explicit `retry_consequential=True`.
- Retries preserve the same request identity and idempotency key.
- Network/transport failures are not blindly retried because the remote outcome
  may be unknown and the SDK cannot infer safe replay semantics.

## Security boundary

The SDK does not decide whether an operation is safe to replay. It only applies
the caller's explicit retry policy to the already-classified operation. Platform
authorization, idempotency authority, execution, and recovery remain server-side.

## Gate

CI must pass lint, formatting, strict typing, tests with at least 90% coverage,
dependency audit, SBOM generation, and CodeQL.
