# M17 — Enterprise Credential & Transport Integrations

M17 provides transport configuration hooks without making the SDK an identity
authority.

Supported integrations:

- caller-owned `credential_provider` for short-lived credential rotation;
- custom CA bundle via `ca_file`;
- mutual TLS via `client_cert` + `client_key`;
- explicit HTTP(S) proxy via `proxy_url`.

Security invariants:

- credentials remain opaque;
- provider results are validated for non-empty/no-whitespace values;
- proxy URLs cannot contain userinfo;
- client certificates require their matching private key;
- no credential material is emitted through telemetry;
- authorization and identity verification remain Platform/deployment-owned.

The credential provider is invoked for each request, allowing applications to
rotate short-lived credentials without rebuilding the SDK client.
