# M14 — Streaming / Realtime Readiness

The SDK does not invent a stream endpoint. The current Platform contract exposes
`runs.events` as a bounded read/list operation only.

M14 is complete for the current Platform baseline when:

1. the SDK explicitly declares streaming as contract-gated;
2. the required future Platform contract identifier is stable;
3. no public streaming method can silently fall back to invented semantics;
4. tests verify the deferred capability declaration;
5. documentation tells implementers exactly what server contract is required.

The future contract must define at least:

- event media type and framing;
- cursor/sequence semantics;
- replay and resume;
- terminal-event semantics;
- cancellation;
- heartbeats;
- backpressure;
- authorization and tenant binding;
- duplicate-event handling;
- maximum stream lifetime;
- failure/reconnect behavior.

When that Platform contract exists, the SDK can publish a typed sync/async stream
surface without changing the authority boundary.
