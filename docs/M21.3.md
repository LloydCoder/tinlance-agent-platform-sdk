# M21.3 — Production State and Resumption Readiness

**Status:** Complete as a fail-closed readiness gate for Platform API 1.1.

## Objective

Define the SDK boundary for durable run inspection and resumption without publishing remote operations that the authoritative Platform contract does not currently expose.

## Current contract

Platform API 1.1 publishes run creation, cancellation, events and evidence references. It does not publish typed operations for run retrieval, waiting, durable state retrieval or resumption.

The SDK therefore keeps these surfaces deferred:

- runs.get
- runs.wait
- resume/state retrieval
- pagination
- webhooks

No speculative endpoint or polling loop is added.

## Upgrade rule

When the Platform publishes a versioned lifecycle/resumption contract, the SDK may add typed RunHandle/Run lifecycle operations only after:

1. the Platform contract is versioned;
2. server-side executable conformance tests exist;
3. request/response schemas and terminal-state semantics are explicit;
4. resume identity and idempotency behavior are defined;
5. crash/recovery and ambiguous-outcome behavior are tested;
6. the SDK compatibility manifest is updated.

## Security boundary

The SDK cannot reconstruct authoritative state from local metadata and cannot turn a resume token into authority. Durable execution identity, tenant binding, authorization and recovery remain Platform responsibilities.
