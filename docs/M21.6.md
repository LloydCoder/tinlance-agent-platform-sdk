# M21.6 — Security and Supply-Chain Certification

**Status:** Complete when the control matrix and all CI/security gates are green.

## Objective

Turn the SDK security posture into an auditable, executable control set covering credentials, tenant binding, authorization boundaries, approvals, endpoint validation, telemetry minimization, dependency integrity and release provenance.

## Certification controls

The authoritative matrix is docs/security/m21-6-control-matrix.json. Every control names a concrete verification source and must remain verified.

The controls align with current OWASP application/agentic risk areas and software supply-chain guidance. External frameworks are alignment references; the repository's tests, workflows and Platform contracts are the evidence sources.

## Supply-chain chain

source commit → CI quality → dependency audit → SBOM → CodeQL → release build → provenance attestation → artifact smoke installation.

The SDK does not claim that an artifact is secure merely because a framework mapping exists. Certification requires the executable gates to be green.

## Platform authority boundary

Security controls that depend on authorization, tenant isolation, approval, sandboxing, evidence integrity or governed execution remain jointly dependent on the authoritative Tinlance Agent Platform. The SDK certifies its client-side behavior and refuses to manufacture server authority.

## Completion gate

M21.6 is complete only when the matrix test, Python quality matrix, package smoke, security workflow and CodeQL are green.
