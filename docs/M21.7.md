# M21.7 — Enterprise Release and Certification

**Status:** Complete when the certification test, CI matrix, security workflow, package smoke gate and release controls are green.

## Objective

Close the M21 program with an auditable release chain from source commit through a fresh package installation and governed reference-agent surface.

## Certification chain

1. Version and contract manifests agree on SDK 1.0.0 and Platform API 1.1.
2. Public SDK operations equal the canonical contract manifest.
3. Deferred operations remain deferred until an authoritative Platform contract exists.
4. The reference ResearchAgent remains a composition helper over runs.create; it does not become a local runtime.
5. CI verifies formatting, typing, tests, coverage, dependency integrity and SBOM generation.
6. CodeQL verifies changed source.
7. Package smoke verifies a fresh wheel installation.
8. Release workflow verifies wheel and sdist, checks the release tag, runs Twine validation, creates build provenance and publishes through trusted publishing.

## Live Platform verification

The repository contains an opt-in live Platform smoke test using the TINLANCE_PLATFORM_TEST_* environment variables. The current committed live test verifies health against Platform API 1.1 and is intentionally skipped in ordinary public CI when deployment credentials are unavailable.

A full governed-execution certification (identity → authorization → approval → tool execution → evidence → audit) remains a deployment-level test responsibility because mutation credentials, approved test tools and a controlled tenant are not appropriate for ordinary public CI. M21.1 certifies the SDK wire contract locally; the Platform repository remains authoritative for server-side R10 execution.

The SDK may observe and serialize the contract; the Platform remains the authority for every governed transition.

## GA boundary

M21.7 is the final planned SDK engineering phase. After this gate, the SDK moves to controlled maintenance and compatibility releases. New remote features must begin with a versioned Platform contract and executable server conformance tests.
